# RouterTasks

Router2API 请求排队与持续保活插件。当前版本 0.3.3，面向 Router2API 2.1.0，C# / .NET 10 后端，JavaScript 管理页面，使用已发布的 Router.Contracts 2.0.0。

插件 ID：`router-tasks`。命名空间：`Plugins.RouterTasks`。

## 添加账号

在「账号任务」点击「添加账号」，统一填写：

- **账号信息**：名称、站点地址、API Key、直连或代理池、代理来源与固定节点、排队 HTTP 状态码、运行模式、模板、模型、提示词来源（固定提示词 / Linux 源码）与源码缓存时长。
- **排队参数**：并发、每轮次数预算、请求间隔、超时、失败重试、完整响应读取。
- **保活参数**：并发、次数预算、心跳间隔、失败重试、失联与掉线确认窗口。
- **请求 JSON**：Headers、Body。
- **通知与记录**：Telegram / Bark、接收方、通知事件、投递重试、日志保留。

每个账号独立保存上述配置。新账号的通知默认关闭。

Claude 账号默认开启「1M 上下文」，可在添加或编辑账号时单独关闭。

填写站点地址和 API Key 后，可直接点击「查询模型 / 额度」。

使用代理池时，可选择全部启用来源、仅手动节点，或勾选指定订阅与手动节点；节点可自动选择，也可固定到其中一个。固定节点仍受来源和可用性限制，已删除、被禁用或处于冷却状态的选择会保留提示，请修改配置后重试。没有符合范围的可用节点时明确失败，不更换范围外节点或回退直连。

模型探针、模型与额度查询、Linux 源码获取使用同一套代理选择规则。每次操作选定一个节点；同一轮模型与额度查询共用该节点和客户端。页面中的查询使用当前表单设置；任务启动或继续时使用保存的配置快照。复制、导入和导出保留代理配置。Telegram 与 Bark 通知继续从宿主直连发送。

API Key、Bot Token、Chat ID、Bark Key 和请求预览完整显示。

保存后点击卡片上的「继续任务」开始运行。编辑运行中的账号前先暂停任务。

## 运行模式

| 模式 | 行为 |
| --- | --- |
| 仅排队 | 按排队参数请求，进入成功后完成；可选择读取完整响应 |
| 持续保活 | 立即发送首次心跳，按保活参数持续请求 |
| 排队后持续保活 | 先排队，成功后自动切换为持续保活 |

切换运行模式会重置本次运行的计数和接受状态，保留历史日志、每日统计及通知回执。保存后点击「继续任务」启动新模式，首次进入通知按新运行重新判断。更新插件时会自动修复旧版本遗留的模式与运行快照不一致的状态。

「允许自动重新排队」开启时，持续失败并确认掉线后重新排队，成功后继续保活；关闭时在确认掉线后自动暂停。单次排队码、网络错误或超时不直接触发重排或掉线通知；尚未取得本次监测的首次成功时，只等待进入，不报掉线。

每轮排队独立计算预算，同时保留累计请求次数。达到预算后停止。

关闭网页后任务继续运行。宿主重启、插件禁用或更新后，任务暂停，等待手动继续。

## 账号卡片

卡片显示运行状态、模型、请求次数、排队轮次、心跳与恢复次数、HTTP 状态和下次请求时间。「本次运行累计」右侧显示账号剩余额度与已用金额；未查询时显示 `—`，无限额度显示「无限制」。额度来自最近一次查询，不代表本次运行消耗。

卡片、线程和日志时间统一按上海时区（`Asia/Shanghai`，UTC+8）显示，并以查看页面的电脑时钟校准宿主记录的时间差。后台请求按配置间隔执行；每日统计按宿主记录的 UTC+8 日期归档。

卡片、日志及线程状态显示最近一次请求实际使用的直连或代理节点；模型与额度查询结果也显示实际节点。节点记录仅包含 ID、来源、地址及可用状态，不包含代理认证信息。

- **编辑**：修改账号连接、运行参数、上下文和通知设置。
- **继续任务 / 暂停任务 / 重新开始**：控制当前任务。
- **日志**：查看此账号的请求日志、每日统计、响应摘要、线程状态和通知记录；恢复此账号暂停的通知投递，也可打开站点使用日志。
- **更多**：复制账号、查询模型与额度、导出账号、立即重试、手动重排、取消和删除。模型与额度查询结果直接更新到账号卡片和模型选项。
- **批量操作**：勾选账号后继续、暂停、取消或删除所选账号。删除前确认，运行中的任务需先暂停；删除失败的账号保留选择并显示原因。

「继续」保留已用预算；「手动重排」开启新一轮；「重新开始」建立新运行记录并重置计数。

## 站点使用日志

在账号卡片「更多 → 使用日志」或「日志统计 → 使用日志」中查询此账号 API Key 的站点记录。后台读取宿主保存的凭据，请求 `GET /api/log/token?key=<账号 API Key>`，保留完整 `sk-` 前缀，并同时发送 Bearer 认证以兼容使用只读 Token 认证的站点。页面管理请求只传账号 ID。

查询复用账号的直连或代理池设置，显示本次实际节点；没有可用代理时明确失败。站点地址结尾的 `/v1` 会移除，部署路径前缀会保留，例如 `/gateway/v1` 对应 `/gateway/api/log/token`。

使用日志显示站点时间（UTC+8）、类型、模型、输入与输出 Token、额度、耗时、流式标记和记录详情。日志时间来自站点，不按宿主时差调整。支持模型／内容搜索、类型筛选、每页 50 条和手动刷新；后台任务继续运行。查询不会保存账号配置、启动任务或发送模型请求。

此接口通常只返回最近记录，没有服务端分页；页面分页与筛选仅针对本次返回的数据。汇总仅计算消费记录（`type=2`），不是账号全部历史消耗，也不等于当前 RouterTasks 运行消耗。`quota` 按站点原始单位显示，不假定美元换算比例；缺失字段显示 `—`。

支持常见的 `{success:true,data:[...]}` 以及 `data.items` 包装。接口不支持、鉴权失败、限流、返回格式不兼容和网络错误均显示具体提示；不会把查询失败显示成暂无记录。查询总超时 20 秒，响应上限 2 MiB，不跟随重定向。结果仅保留在当前页面，不写入插件历史文件；上游反射的账号 Key 会隐藏，网络错误不回传带 Key 的请求 URL。

已完成、已接受后中断的仅排队请求，以及当前阶段预算耗尽的任务，主按钮显示「重新开始」，点击后确认。提高预算或增加并发后仍有可用次数时显示「继续任务」。批量继续会跳过需要重新开始的账号，并显示账号名称及原因。

## 请求与判定

- 排队 HTTP 状态码默认 `500`，多个值使用逗号分隔；`[]` 关闭状态码匹配。
- HTTP 401、402、403 和明确的鉴权、额度错误停止任务。
- 网络错误与超时分别设置重试，间隔遵守更长的 `Retry-After`。
- HTTP 408、425、429、5xx（无明确永久错误时）和未取得有效接受事件的协议异常按阶段预算和重试间隔重试。
- 任一并发线程收到正式接受事件即算成功；其他线程的临时失败不能抢先取消可能成功的请求。明确永久错误仍立即停止。
- Responses 的接受事件为 `response.created` / `response.in_progress`。
- Messages 的接受事件为 `message_start`。
- 接受事件表示服务已经接受请求，回答完成以协议完成事件为准。
- 完整响应的成功终态为 Responses `response.completed`、明确包含 `response.status=completed` 的 `response.done`，或 Messages `message_stop`。终态内的失败、取消、未完成状态或错误不会算作完整成功；单独的 `[DONE]` 只表示流结束。
- 已接受后的 EOF、超时或协议错误记为响应中断，不自动重放模型 POST。暂停、取消和插件停止优先于超时及缓冲的完成帧，等待在途请求退出后再结束任务。

每次请求生成新的会话身份，同一请求的 Headers 与 Body 共享变量值。启动或继续任务时保存配置快照。

## 默认参数

| 参数 | 默认值 |
| --- | --- |
| 排队并发 / 保活并发 | 1 / 1 |
| 每轮排队预算 | 每线程 300 次 |
| 保活阶段预算 | 不限 |
| 排队间隔 | 10 秒 |
| 心跳间隔 | 120 秒 |
| 保活失败重试间隔 | 15 秒 |
| 首事件超时 | 60 秒 |
| 失联窗口 / 掉线确认窗口 | 300 秒 / 120 秒 |
| 完整响应总超时 / 空闲超时 | 600 秒 / 60 秒 |
| 单次响应上限 | 2 MiB |
| Linux 源码缓存时长 | 360 分钟（6 小时） |
| 事件记录上限 | 每账号 200 条 |
| 响应摘要上限 | 每账号 8192 字节 |
| 通知保留 | 每账号 30 天、1000 条 |
| 通知投递次数 / 初始间隔 / 最大退避 | 10 次 / 5 秒 / 3600 秒 |

请求间隔和心跳间隔支持随机范围，并发使用异步 I/O。各账号分别设置参数。

后台探针使用独立 HTTP 客户端，由插件的首事件、完整响应和空闲超时控制，不经过宿主模型路由的 300／180 秒建立预算。管理查询另有 20 秒总超时，源码获取为 8 秒；管理请求还受宿主端点超时限制。客户端复用宿主物理连接池，每次操作结束归还租约，不叠加隐式模型 POST 重试。

## 请求模板

「请求模板」提供 OpenAI Responses（`/v1/responses`）和 Anthropic Messages（`/v1/messages`）预设，支持复制与 JSON 编辑。接口按协议自动选择。

模板 JSON 在输入框内滚动，保存按钮固定显示。

变量包括 `{{TOKEN}}`、`{{MODEL}}`、`{{PROMPT}}`、`{{CURRENT_DATE}}`、`{{SESSION_ID}}`、`{{TURN_ID}}`。

`{{TOKEN}}` 使用账号的 API Key。模型请求为 POST / SSE，`Body.stream` 为 `true`。

模型、提示词与 Body JSON 双向编辑，保留其他字段和数值精度。请求预览显示展开后的完整内容。

在「账号信息 → 提示词来源」选择「固定提示词」或「Linux 源码」，两者互斥，不拼接。

- 固定提示词：只使用填写的内容，不获取 Linux 源码。
- Linux 源码：从 GitHub 获取源码片段作为分析提示词，正常获取或有缓存时不发送固定提示词；切回固定模式时保留之前填写的内容。
- 缓存时长按账号设置，单位为分钟，支持小数，范围 0–2000000，默认 360（6 小时）。0 表示每次请求尝试刷新；正数到期后在下一次请求时刷新，不是后台定时下载。
- 源码片段缓存由插件内账号共享，各账号按自己的时长判断是否需要刷新。
- 获取失败时只使用已有源码缓存；没有可用源码缓存时回退到固定提示词，失败重试间隔为 10 分钟。成功获取后不受失败重试间隔限制。
- Linux 模式的请求预览也使用源码与相同缓存规则，只获取源码，不发送模型请求。

## 账号通知

通知从宿主直接发送。

每个账号分别配置 Telegram Bot Token、Chat ID、Bark 服务地址和设备 Key，选择启用的渠道及通知事件。

通知依据业务状态变化，而不是每次请求的成败；仅发送已勾选的事件，两个渠道独立投递和重试。

| 事件 | 何时通知 |
| --- | --- |
| 首次进入 | 本次运行第一次收到正式 SSE 接受事件时一次；不等同于完整回答完成。普通心跳、继续、手动重排不重复发送；显式重新开始或切换运行模式是新运行 |
| 确认掉线 | 曾确认会话后，距上次成功达到失联窗口（默认 300 秒）才开始观察；从实际进入观察起再持续失败满确认窗口（默认 120 秒），在下一次失败结果上确认，通知一次 |
| 确认掉线后恢复 | 只有已确认的掉线再次收到正式接受事件时通知一次；观察期内恢复只记日志，不累计“恢复次数”，也不推通知。即使未勾选掉线事件，也可单独勾选此项 |
| 错误停止 | 鉴权、额度、模型/请求配置等不可重试错误，或执行异常使任务停止时通知 |
| 自动暂停 | 确认掉线但关闭自动重排，或明确关闭了对应网络/超时重试，导致任务需要人工处理时通知 |
| 次数预算耗尽 | 当前阶段所有线程的请求次数预算耗尽、任务实际停止时一次；继续未增加预算，不重复通知 |

确认掉线且关闭自动重排时，掉线与自动暂停合并通知，优先发送已勾选的「确认掉线」，内容说明任务已暂停；只勾选自动暂停时发送「自动暂停」。正常排队、短暂失败与恢复、用户暂停/取消、插件停止只记日志。掉线确认窗口为 0 时无需额外观察。观察期间按失败重试间隔尝试，成功后清除计时；确认掉线后按排队参数开启新轮次。

暂停清除观察计时，保留已确认故障至下一次成功。掉线/恢复按运行编号和故障编号去重，停止事件按阶段、轮次及请求次数去重。通知包含中文标题及事件发生时间（UTC+8）。

重启后未完成的投递暂停，可在对应账号的「日志统计」中恢复。投递中断时可能已经送达，恢复投递可能重复。

仅开启通知渠道或普通继续不会补发此前发生的事件；通知在下一次已勾选的业务事件发生时入队。

## 导入与导出

卡片「更多 → 导出账号」生成账号 JSON，包含站点、API Key、运行参数、完整请求模板、通知设置和通知凭据。

在「导入账号」选择 JSON 文件，检查表单后保存为新账号。

## 数据

- API Key 与账号通知凭据保存在宿主账号服务。
- 配置、快照、计数、事件和通知回执使用版本化 JSON、串行写入及原子替换。
- 默认数据目录为宿主程序目录下的 `data/plugins/router-tasks`。
- 环境变量 `ROUTER2API_ROUTERTASKS_DATA_DIR` 可指定持久化数据目录。
- `state.json` 保存状态，`state.json.bak` 保存上一版本，`writer.lock` 提供单实例写锁。

## 构建与安装

需要 .NET 10 SDK、Node.js 24、PowerShell 7。

```powershell
Set-Location D:\Scan\Router2API\RouterTasks
npm ci
pwsh -File .\test.ps1 -Browser
pwsh -File .\package-release.ps1
```

浏览器检查使用本机 Chrome，也可通过 `BROWSER_EXECUTABLE` 指定浏览器路径。

`test.ps1 -Browser -HostIntegration` 运行页面检查、宿主加载与热更新、程序集回收、SQLite 凭据持久化验收。使用 `-RouterHostProject` 指定隔离宿主源码中的 `Router.Host.csproj`；本地已配置 `artifacts/host-source-path.txt` 时可省略。`-PluginZip` 可指定待验收的发行包。

宿主验收仅访问本机回环地址，报告保存在 `artifacts/acceptance`。

插件包输出到 `artifacts/release`，包含 ZIP、SHA-256 文件及发行索引。

在 Router2API 插件管理页上传 `router-tasks.zip`。更新前备份业务数据和宿主账号数据，保留旧插件包用于回退。

## GitHub 自动发行

仓库的 `v*` 标签会触发 GitHub Actions：使用 .NET 10 构建插件，生成 `router-tasks.zip`、SHA-256、`release-index.json` 和发行说明，并自动发布 GitHub Release。标签必须与插件版本一致。

零补丁版本支持简写标签，例如 `v0.3` 对应项目版本 `0.3.0`，页面显示 `v0.3`；打包默认使用简写。补丁版本使用完整标签，例如 `v0.3.1`。

手动运行 `Release RouterTasks` 时默认只打包：`tag` 留空使用所选分支，填写后构建指定的已有标签。勾选 `publish_release` 可以从该标签发布 Release，必须明确填写标签，不会创建、移动或覆盖 Git 标签。构建产物保留 14 天；发行文件长期保存在 Release。
